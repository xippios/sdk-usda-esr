# Upstream documentation snapshot — USDA FAS Export Sales Reporting

Source of truth for every endpoint wrapper (sdk-core ADR-0028). The files in this
directory are written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the
pages in the table below and refreshed deliberately by PR, so that changes show up as
diffs. This file is generated by the same script; nothing here is edited by hand but
`OBSERVED.md`, where it exists: what upstream does but never documents, each note with
its evidence.

## Attribution

None stated: no page this script reads states a copyright line, a licence or terms of
use.

The script stops when a page it reads states one it does not record, or no longer prints
one it records. The documentation's text is reproduced here as this package's reference
(sdk-core ADR-0028); the publisher's objection is met by replacing it with a summary
that keeps the names and semantics the wrappers rely on.

## How this is captured

The FAS Open Data Services portal, https://apps.fas.usda.gov/opendatawebV2/, documents
three APIs of USDA's Foreign Agricultural Service: ESR, GATS and PSD. It is an Angular
app whose page is a shell without documentation text. Its Swagger window loads the
Swagger 2.0 document
https://apps.fas.usda.gov/opendatawebV2/assets/swagger/swagger.json. On 2026-10-23, when
sdk-usda-psd's snapshot was set up, the portal page and its JavaScript bundle were
fetched into a temporary directory and that URL was found in the bundle's Swagger UI
configuration; those copies have since been deleted, and this script reuses the URL. The
script never downloads the bundle, since it embeds the portal's own api.data.gov
signup-widget key, and this file records only its file name, in the portal page's row.

The API also serves its own Swashbuckle document, which the classic Swagger UI at
https://apps.fas.usda.gov/opendata/swagger/ui/index loads; the script reads its URL from
the UI page's `rootUrl` and `discoveryPaths`, and the UI page's row names it.

Both documents cover ESR, GATS and PSD, and GATS and PSD get their own packages in this
family, so each file here holds the ESR part only: every top-level field verbatim and in
upstream order, `paths` reduced to the keys starting with `/api/esr/` and `definitions`
reduced to those the kept paths reference, directly or through other definitions; each
document's row counts the paths kept and dropped, per prefix. The script writes the part
with `json.dumps(indent=2, ensure_ascii=False)` in upstream key order, with LF line
endings and a final newline, and stops unless the full document re-serialised the same
way reproduces the fetched text up to line endings, so each file is the upstream text
with the other APIs cut out.

The portal page and the classic Swagger UI page are client-rendered shells without
documentation text: each gets no file, only a row with its HTTP status and the size and
sha256 of its body, and a shell larger than 16384 bytes, or without its mount point,
stops the run.

Pages that answer 404 get no file, only a row with their HTTP status and the size and
sha256 of the body. The ESR query URLs https://apps.fas.usda.gov/esrquery/ and
https://apps.fas.usda.gov/esrquery/esrq.aspx were expected, when this snapshot was set
up on 2026-10-25, to serve the ESR query application's client-rendered shell; both
answer 404, and their rows record what is answered. The Export Sales Reporting program
page, https://www.fas.usda.gov/programs/export-sales-reporting-program, answers 403
Access Denied at the CDN edge to headless clients, a body that carries a per-request
reference number.

Fetched is the UTC time the run started, in ISO 8601 with an explicit Z, the same for
every row. Bytes and sha256 are those of the body as fetched: a converted page's row
holds the HTML page's, an excerpt's the whole document's, a file split from a page the
page's. Last-Modified is the HTTP header in UTC, or as sent in a code span where it is
no HTTP date, and ETag is as sent, in a code span, on a row that ends in a comment
telling the secret scan it is no key. A page recorded without a file is `(no file)`, and
a body that changes on every request records no size, sha256 or ETag. A sample is a
small answer of the API kept verbatim under `samples/`, which documents the answer's
shape and is no test fixture. Requests go one at a time, 2 s apart, through core's
client, each retried at most once and no sooner than 10 s, a 429 after the wait the
client gives it where that is longer, and are identified as `xippios-usda-esr/<version>
(+https://github.com/xippios)`, the source package's version in place of `<version>`. No
redirect to another host is followed and no browser is imitated. No key is sent or read.
A page an anonymous client cannot read is requested once and listed under Not fetched.

## The two documents

Both documents are kept because they are two upstream statements of the same API that
need not agree on how it is reached. As fetched, their ESR parts differ in `host` and
`securityDefinitions`; only the portal document has `security`; only the backend
document has `basePath`; they agree in `swagger`, `info`, `schemes`, `paths` and
`definitions`; the `info` object of each carries only `version`, `title` and
`description`.
