# Upstream documentation snapshot — USDA FAS Export Sales Reporting

Source of truth for every endpoint wrapper (ADR-0003). The files in this directory are
written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the documents in the
table below and refreshed deliberately by PR, so that changes show up as diffs. This
file is generated by the same script. Nothing here was edited by hand.

## Attribution

Neither document states a copyright line: the `info` object of each carries only
`version`, `title` and `description`, with no `license`, `termsOfService` or `contact`,
and neither document's text contains a copyright sign or the word copyright. The script
stops if either comes to state one. The documents' text is reproduced here as this
package's reference (ADR-0003); a vendor's objection is met by replacing it with a
summary that keeps the names and semantics the wrappers rely on.

## How this is captured

The FAS Open Data Services portal, https://apps.fas.usda.gov/opendatawebV2/, documents
three APIs of USDA's Foreign Agricultural Service: ESR, GATS and PSD. It is an Angular
app whose page is a shell without documentation text. Its Swagger window loads the
Swagger 2.0 document
https://apps.fas.usda.gov/opendatawebV2/assets/swagger/swagger.json. On 2026-10-23 the
session that set up sdk-usda-psd's snapshot fetched the portal page and its JavaScript
bundle into a session-local scratch directory and found that URL in the bundle's Swagger
UI configuration; those copies have since been deleted, and this script reuses the URL.
The script never downloads the bundle, since it embeds the portal's own api.data.gov
signup-widget key, and this file records only its file name: as of this run the portal
page loads `main.6da18f8b4fa8a2baed40.js`.

The API also serves its own Swashbuckle document,
https://apps.fas.usda.gov/OpenData/swagger/docs/v1, which the classic Swagger UI at
https://apps.fas.usda.gov/opendata/swagger/ui/index loads; the script reads that URL
from the UI page's `rootUrl` and `discoveryPaths`. Both documents are kept because they
are two upstream statements of the same API that need not agree on how it is reached. As
fetched, their ESR parts differ in `host` and `securityDefinitions`; only the portal
document has `security`; only the backend document has `basePath`; they agree in
`swagger`, `info`, `schemes`, `paths` and `definitions`.

Both documents cover ESR, GATS and PSD, and GATS and PSD get their own packages in this
family, so each file here holds the ESR part only: every top-level field verbatim and in
upstream order, `paths` reduced to the keys starting with `/api/esr/` and `definitions`
reduced to those the kept paths reference, directly or through other definitions; each
document's row counts the paths kept and dropped, per prefix. The script writes the part
with `json.dumps(indent=2, ensure_ascii=False)` in upstream key order, with LF line
endings and a final newline, and stops unless the full document re-serialised the same
way reproduces the fetched text up to line endings, so each file is the upstream text
with the other APIs cut out. Bytes and sha256 in a document's row are those of the full
document as fetched, so a change anywhere in it shows here.

Pages that are client-rendered shells, that refuse headless clients or that answer 404
get no file, only a row with their HTTP status and the size and sha256 of the body. The
ESR query URLs https://apps.fas.usda.gov/esrquery/ and
https://apps.fas.usda.gov/esrquery/esrq.aspx were expected, when this snapshot was set
up on 2026-10-25, to serve the ESR query application's client-rendered shell; both
answer 404, and their rows record what is answered. The program page's 403 body carries
a per-request reference number and so is not stable; its row records neither size nor
sha256. The same upstream thus gives the same files under `openapi/`, and this file
differs between runs only in `Fetched`.

`Fetched` is the UTC time of the run in ISO 8601 with an explicit `Z`, taken once at its
start and the same in every row (conventions §3); Last-Modified is the HTTP header in
UTC, ETag as sent. Requests go one at a time, identified as `xippios-usda-esr
refresh_upstream (+https://github.com/xippios)`; no API key is sent or read.
